# Token 历史系统日期选择器设计

## 目标

调整“Token 使用与成本”窗口的日模式日期控件：将左侧文案从“所在周”改为“日期选择”，恢复 macOS 系统紧凑型日期选择器及其日历下拉菜单，并去掉当前 `124pt` 固定宽度造成的多余留白。

## 交互与布局

- 日模式继续用所选日期查询该日期所在自然周，不改变统计口径。
- 文案显示为“日期选择”。
- 日期控件显示为内容固有宽度的系统按钮；点击后通过 popover 展示 SwiftUI 图形化 `DatePicker`，使用 macOS 默认日历选择日期。
- 日历控件隐藏自身标签，由外部“日期选择”提供说明；选择日期后自动收起 popover。
- 控件通过 `fixedSize(horizontal: true, vertical: false)` 按系统固有内容宽度排列，不设置固定宽度；不同日期格式或地区设置可由系统自行适配。
- 文案、日期控件与范围选择器继续保持在同一行。

## 实现边界

- 只修改日模式的日期控件和直接相关测试。
- 移除不再使用的 `TokenHistoryWeekDatePicker` 自定义 AppKit 包装，避免保留死代码。
- 不修改 `selectedDay` 状态、自然周区间解析、其他范围模式、图表或窗口布局。

## macOS 14 验证修正

实际启动验证确认 SwiftUI `.compact` 日期样式在当前 macOS 14 环境中只呈现文本与步进器，不会弹出日历。因此采用系统按钮承载 popover，并在其中使用 `.graphical` 系统日期选择器，以满足“下拉选择默认日历”的交互要求。

## 验证

- 先添加期望“日期选择”和系统日期控件的回归测试，确认它在当前实现下因“所在周”和自定义固定宽度控件而失败。
- 渲染测试确认“日期选择”和日期值可见并保持同一行。
- 实际启动应用，确认点击日期控件会打开系统日历菜单并能选择日期。
- 运行完整非基准测试、Release 构建、应用启动验证和 `git diff --check`。
