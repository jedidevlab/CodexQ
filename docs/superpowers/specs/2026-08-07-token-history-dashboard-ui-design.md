# Token 历史仪表盘 UI 设计

## 目标

将现有 `Token 使用与成本` 历史窗口调整为更接近参考图的信息层级：清晰的标题区、分行筛选区、统一摘要卡片、宽窗口双栏趋势图和整行模型分布。同时保留现有数据来源、查询模式、统计规则和交互能力。

根窗口不写死黑色或白色背景，使用 macOS 默认窗口背景，自动跟随系统浅色与深色外观。

## 范围

本次只修改 Token 历史窗口，不修改菜单栏弹窗、设置窗口或数据读取逻辑。

保留以下现有能力：

- `日 / 月 / 年 / 订阅周期 / 自定义` 五种查询模式。
- 当前范围对应的日期、年月、订阅周期或自定义日期控件。
- Token 总量、估算成本、日均 Token、日均成本四项摘要。
- Token 趋势、估算成本趋势、模型分布三张图表。
- 共享悬浮选择、键盘左右切换、Escape 清除选择。
- 数据范围、官方活动覆盖、未计价 Token、同步和刷新错误提示。
- `API 价格估算，非实际订阅账单` 说明。

不增加参考图中的工具、项目、终端、时长、会话数、消息数、分享或同步按钮，也不改变已有成本和 Token 计算规则。

## 窗口与响应式布局

- 默认窗口内容尺寸调整为 `1080 × 720`。
- 最小窗口尺寸调整为 `840 × 600`。
- 窗口继续使用现有 autosave 名称，保留用户调整后的大小和位置。
- 宽度足够时，Token 趋势和估算成本趋势左右等宽排列。
- 宽度不足时，两张趋势图自动恢复纵向排列，避免坐标轴、提示和筛选控件裁切。
- 模型分布始终单独占据整行。
- 内容超出高度时继续由窗口内滚动区承载。

## 信息层级

### 标题区

第一行左侧显示 `Token 使用与成本`，右侧显示加载指示和刷新按钮。标题不与时间范围分段控件挤在同一视觉组中。

### 筛选区

第二行显示范围模式分段控件，突出当前选择。

第三行显示当前模式对应的日期控件。数据范围说明与估算免责声明放在同一辅助信息区，使用次级文字样式。

不新增参考图中的工具、模型、项目和终端筛选，因为现有历史数据模型不支持这些维度。

### 摘要卡片

四张摘要卡横向等宽排列：

1. Token 总量
2. 估算成本
3. 日均 Token
4. 日均成本

卡片采用统一的系统自适应容器底色和细边框。背景不使用蓝、绿、橙等整块染色；强调色只用于关键数值或小型图标。数值继续使用等宽数字、单行和缩放保护。

### 图表区

- Token 趋势卡和估算成本趋势卡在宽窗口中组成两列。
- 两张卡继续共享同一个时间桶选择。
- 每张卡保留标题、坐标轴、平均线或面积线、悬浮提示和无数据状态。
- 模型分布卡放在下一行并占满宽度，保留 `Token / 成本` 切换。

## 颜色与材质

- 根视图不设置自定义黑色、白色或固定 RGB 背景。
- 根视图直接使用系统默认窗口背景。
- 摘要卡和图表卡使用系统自适应的控制背景或材质，并用系统分隔色形成边界。
- 正文使用 `.primary`，辅助说明使用 `.secondary`，告警继续使用语义化橙色或红色。
- 图表的 Token 使用系统强调色，成本使用绿色；颜色不是唯一信息载体，文字和辅助功能标签继续说明含义。

## 状态与交互

加载、空数据、首屏错误、保留上次数据后的刷新错误逻辑不变。布局调整不得触发额外数据读取，也不得改变 `TokenHistoryStore` 的状态所有权。

在默认宽度与最小宽度下都必须满足：

- 五种筛选可以操作且不裁切。
- 四张摘要卡可读。
- 图表可滚动且坐标轴不重叠到不可读。
- 键盘和辅助功能行为继续有效。

## 验证

采用测试驱动实现：

1. 先增加失败的 UI 源码契约测试，固定默认窗口尺寸、最小尺寸、系统自适应背景、分行筛选、摘要卡统一容器和响应式双栏图表。
2. 确认测试因当前布局缺少这些契约而失败。
3. 做最小 SwiftUI 调整使测试通过。
4. 运行 `TokenHistoryViewTests`、相关历史查询测试和现有弹窗回归测试。
5. 运行 `swift build -c release` 与 `./script/build_and_run.sh --verify`。
6. 在实际窗口中分别检查默认尺寸、最小尺寸、浅色/深色自适应背景、宽窗口双栏和窄窗口纵向回退。

## 成功标准

- 历史窗口在信息层级和卡片布局上明显接近参考图，但不复制无数据支撑的功能。
- 背景不再固定为黑色，完全跟随 macOS 默认外观。
- 默认宽度呈现双栏趋势图，窄窗口自动纵向排列。
- 四张摘要卡样式统一，不使用整块彩色背景。
- 数据、筛选、图表选择、错误状态和无障碍能力无回归。
- 工作区只包含本次设计与实现相关改动。
