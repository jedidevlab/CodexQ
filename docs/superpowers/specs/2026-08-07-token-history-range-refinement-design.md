# Token 历史日期范围精简设计

## 目标

完善“Token 使用与成本”窗口的日期范围选择：保留“日、月、年、订阅周期、自定义”，新增“累计”，不增加“周”。同时让“日”展示所选日期所在自然周的 7 个每日数据，并收窄订阅周期选择器。

## 交互与统计口径

- “日”默认选中今天，因此首次进入时展示本周 7 天；日期控件可选择其他日期，并展示该日期所在自然周。
- 自然周遵循传入日历的周设置，范围始终为连续 7 个本地自然日，图表按日聚合。
- “累计”不显示额外日期控件；范围从本地会话记录或官方活动数据中最早的有效日期开始，到今天结束。
- 累计范围不超过 92 天时按日聚合，不超过 3 年时按月聚合，更长时按年聚合，沿用自定义长范围的现有规则。
- 若累计模式没有任何历史记录，仍返回今天这一自然日的空结果，避免无效选择错误。
- 订阅周期选择器使用固定的合理宽度并允许系统截断长标签，不再占满标题栏剩余空间。

## 实现边界

- 在日期范围枚举与选择枚举中增加“累计”，不增加周粒度或周筛选控件。
- 将现有单日区间解析改为所选日期所在自然周。
- 累计区间在聚合器拿到会话记录、官方活动和当前时间后解析，避免 Store 猜测数据起点。
- 不修改月、年、订阅周期、自定义的既有统计口径。
- 不改变数据读取来源、价格计算、窗口路由或其他仪表盘布局。

## 验证

- 查询测试覆盖本周恰好 7 天、跨月自然周、累计起止日期、空数据累计和累计聚合粒度。
- 渲染测试覆盖“累计”选项可见、日模式显示周选择语义、订阅周期选择器宽度受限。
- 运行 Token 历史相关测试、完整非基准测试、Release 构建和实际应用启动验证。
