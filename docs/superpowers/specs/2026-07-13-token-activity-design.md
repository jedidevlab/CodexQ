# CodexQ Token 活动设计

## 目标

在现有菜单栏弹窗中加入 Codex 账户的 Token 活动视图。数据口径与 Codex 客户端保持一致，不新增独立设置页面。

## 数据来源

- 通过本机 Codex app-server 的账户 Token Usage 接口读取 `summary` 与 `dailyUsageBuckets`。
- 服务端 `yyyy-MM-dd` 日期始终按公历和本机时区解析、分组及格式化，不受系统首选日历影响。
- 不直接读取或输出用户认证信息。
- 每次刷新额度时同步刷新 Token 活动。
- Token 活动读取失败时保留现有额度结果，并在活动区域显示“Token 活动暂不可用”。

## 展示范围与结构

现有额度块下方新增一个“Token 活动”区域，仅展示每日活动。

### 每日视图

- 根据弹窗宽度自动计算可容纳的周列数，以连续热力图合并显示，不按月份拆分网格。
- 当前 256 pt 弹窗在扣除水平内边距后可显示 16 个周列；数据不足时以空方块补齐较早日期。
- 每个日期对应一个独立方块。
- 缺失日期补为空方块，保持连续的日历结构。
- 每列代表一周、每行代表一周中的一天；当前周只显示到今天，不绘制未来日期方块。
- 月份标签显示在热力图下方，并按对应周列范围居中。

## 视觉与交互

- 方块样式、间距和圆角保持统一，并与 Token 活动的块状表达一致。
- 颜色深浅表示当天 Token 使用量等级。
- 悬停方块显示具体日期和当天 Token 数量。
- 所有日期方块使用完全相同的 Token 数量单位及格式化规则。
- “Token 活动”标题右侧以无背景、无边框的单行文字显示最近完整日与“累计 Token”；最近完整日恰好是昨天时显示“昨日”，否则显示具体月/日。两项沿用相同的紧凑数量格式，数值后不重复显示 `tokens` 字样。
- 最近完整日或累计数据缺失时显示“暂无数据”，不把缺失值解释为 0。
- 缺失日期与无使用量日期保持空方块语义，不显示虚构数据。

## 状态与边界

- 加载中：活动区域显示紧凑的加载状态，不阻塞现有额度内容。
- 空数据：显示完整日期结构和空状态说明。
- 请求失败：显示明确错误状态，现有额度仍可正常刷新和使用。
- app-server 不支持 Token Usage 接口时按请求失败处理，不回退到本地会话估算。

## 代码边界

- 为账户 Token Usage 响应增加独立模型和解码逻辑。
- 日期裁剪、缺失日期补齐、颜色等级和 Token 格式化使用可独立测试的纯逻辑。
- 在现有 store 中增加活动状态，但不改变现有额度、通知和缓存行为。
- SwiftUI 活动区域作为独立小视图嵌入现有 `QuotaPopoverView`，遵循项目当前样式。

## 验证标准

- 每日视图按弹窗宽度自动扩展可见周数，并合并为连续热力图。
- 跨月、跨年及缺失日期行为有自动化测试。
- app-server 响应解码、空数据和失败状态有自动化测试。
- 所有日期方块显示相同 Token 单位并使用相同颜色等级规则。
- 全量测试通过，应用构建成功，菜单栏弹窗在实际运行中可正常显示活动方块。
