# CodexQ Token 活动设计

## 目标

在现有菜单栏弹窗中加入 Codex 账户的 Token 活动视图。数据口径与 Codex 客户端保持一致，不新增独立设置页面。

## 数据来源

- 通过本机 Codex app-server 的账户 Token Usage 接口读取 `summary` 与 `dailyUsageBuckets`。
- 不直接读取或输出用户认证信息。
- 每次刷新额度时同步刷新 Token 活动。
- Token 活动读取失败时保留现有额度结果，并在活动区域显示“Token 活动暂不可用”。

## 展示范围与结构

现有额度块下方新增一个“Token 活动”区域，顶部使用分段控件切换“每日”和“每周”，默认显示“每日”。

### 每日视图

- 展示最近 3 个自然月内的每日数据。
- 每个日期对应一个独立方块。
- 缺失日期补为空方块，保持连续的日历结构。

### 每周视图

- 展示最近 2 个自然月内的每日数据。
- 按自然周分组，一周从周一开始。
- 每周内部保留周一至周日 7 个独立方块，不汇总为周 Token 总数。
- 跨月和跨年周仍按自然周连续展示；范围外日期显示为空方块，不混入统计。

## 视觉与交互

- 方块样式、间距和圆角保持统一，并与 Token 活动的块状表达一致。
- 颜色深浅表示当天 Token 使用量等级；同一份数据在每日和每周视图中使用相同的颜色分级规则。
- 悬停方块显示具体日期和当天 Token 数量。
- 每日与每周视图使用完全相同的 Token 数量单位及格式化规则，切换视图不得改变数值单位。
- 无使用量与范围外日期在视觉上可区分，但均不显示虚构数据。

## 状态与边界

- 加载中：活动区域显示紧凑的加载状态，不阻塞现有额度内容。
- 空数据：显示完整日期结构和空状态说明。
- 请求失败：显示明确错误状态，现有额度仍可正常刷新和使用。
- app-server 不支持 Token Usage 接口时按请求失败处理，不回退到本地会话估算。

## 代码边界

- 为账户 Token Usage 响应增加独立模型和解码逻辑。
- 日期裁剪、缺失日期补齐、自然周分组、颜色等级和 Token 格式化使用可独立测试的纯逻辑。
- 在现有 store 中增加活动状态，但不改变现有额度、通知和缓存行为。
- SwiftUI 活动区域作为独立小视图嵌入现有 `QuotaPopoverView`，遵循项目当前样式。

## 验证标准

- 每日视图只包含最近 3 个自然月。
- 每周视图只覆盖最近 2 个自然月，并且每周固定包含 7 个每日位置。
- 周一分组、跨月、跨年及缺失日期行为有自动化测试。
- app-server 响应解码、空数据和失败状态有自动化测试。
- 两种视图对同一天显示相同 Token 数量、相同单位和相同颜色等级。
- 全量测试通过，应用构建成功，菜单栏弹窗在实际运行中可正常切换并显示活动方块。
