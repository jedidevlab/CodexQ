# CodexQ iCloud Drive 脱敏成本账本设计

## 目标

让同一个 Codex 账号在多台 Mac 上使用 CodexQ 时，可以通过用户主动选择的 iCloud Drive 文件夹合并 Token 成本，同时保持现有 Token 活动、额度刷新和本机离线使用能力不变。

本方案不依赖 Apple 开发者账号、CloudKit、应用签名能力或 CodexQ 自建服务器。iCloud Drive 只作为普通文件同步通道，CodexQ 只读写用户明确选择的文件夹。

## 产品口径

- Token 活动继续使用 app-server 返回的账号级数据，不读取同步文件夹，也不因同步开关改变。
- Token 成本关闭同步时只统计本机 `.codex/sessions`。
- Token 成本开启同步且文件夹可用时，统计本机与同步文件夹内通过校验的全部设备账本。
- 额度、套餐类型、重置额度、通知和耗尽预测不参与同步。
- 同步的是可重新计算成本的脱敏 Token 用量事实，不同步美元金额。
- 同步账本是历史账本：本机会话被清理后，已经写入的历史用量仍然保留。
- 所有同步能力默认关闭，只有用户主动开启并成功选择文件夹后才开始写入。

## 非目标

- 不使用 CloudKit、iCloud Container 或 iCloud Key-Value Store。
- 不自动扫描、复制或移动整个 `.codex/sessions` 目录。
- 不同步提示词、回复、会话标题、工作目录、文件路径或 Git 信息。
- 不同步 Codex 登录令牌、认证文件、原始账号标识或订阅凭据。
- 不同步 Token 活动热力图、额度快照或通知设置。
- 不提供跨 Apple 账号共享、团队账单、网页后台或设备远程管理。
- 第一版不提供 CodexQ 自有端到端加密；“脱敏”不能描述成“加密”。
- 第一版不把删除本机会话解释为删除云端历史账本。

## 设置入口

沿用弹窗底部齿轮打开的内嵌设置，不新增独立设置窗口。

在“登录时启动”和“额度预警通知”下方增加：

- 复选项：`iCloud 同步`
- 开启后在复选项右侧显示按钮：`更换文件夹…`
- 不显示文件夹名称或完整路径。

开启复选项时立即打开系统文件夹选择器：

1. 用户选择一个 iCloud Drive 文件夹。
2. CodexQ 验证文件夹可读、可写，并检查或创建账本清单。
3. 验证成功后才把开关保存为开启。
4. 用户取消选择或验证失败时，开关保持关闭，不产生账本文件。

文件夹选择器默认引导用户进入 iCloud Drive，但不通过内部路径硬编码判断云服务。用户选择 Dropbox、OneDrive 等普通同步文件夹时也可以工作；界面仍明确说明 CodexQ 不能保证第三方同步服务的时效。

## 设置内说明形式

在同步复选项下方固定显示一张紧凑的两行“数据影响说明卡”，不把关键影响藏在帮助气泡里。

关闭时显示：`未开启：活动不变；成本仅统计本机。`

开启且同步正常时显示：`Token 活动不影响；成本汇总多台 Mac。`

开启但同步异常时显示：

- 同步暂停：`同步暂停：活动不变；成本仅统计本机。`
- 同步延迟：`同步延迟：活动不变；成本显示最近数据。`

说明卡下方使用更弱的辅助文字：

`仅同步模型、时间和 Token 数，不含会话及登录信息。`

这张说明卡随开关和同步状态更新，并触发现有弹窗高度重算。设置关闭时仍保留说明卡，避免用户误以为 Token 活动也会变成本机数据。

## Token 成本区域变化

Token 成本标题旁现有的 `本机数据` 标签按实际数据范围变化：

- 同步关闭：`本机数据`
- 同步开启且至少读取到一个有效远端设备账本：`多设备数据`
- 同步开启但当前文件夹不可用：`多设备 · 同步延迟`
- 同步开启但只有本设备账本：`仅此设备`

成本卡片、今日、昨日、本订阅周期、累计和模型明细的结构保持不变。

模型明细底部说明按数据范围变化：

- 本机：`本机数据，按官方 API 价估算，非实际账单`
- 单设备同步：`仅本地数据，按官方 API 价估算，非实际账单`
- 多设备同步：`多设备数据，按官方 API 价估算，非实际账单`

同步失败不能清空现有成本。界面继续显示本机数据与上次成功合并结果，并给出紧凑错误说明。

## 数据边界

### 允许进入账本的字段

每条用量事实只包含：

- 不可逆事件标识
- UTC 发生时间
- 模型名称
- 输入 Token
- 缓存输入 Token
- 缓存写入 Token
- 输出 Token
- 总 Token
- 服务档位
- 账本格式版本

### 禁止进入账本的字段

- 原始会话 ID
- 原始账号 ID
- 设备名称、用户名、主机名或硬件序列号
- 提示词、回复、工具调用参数或工具输出
- 会话标题、工作目录、仓库地址或分支
- 文件名、原始 session 路径或 session JSONL 内容
- access token、ID token、refresh token、cookie
- 订阅开始和结束声明的原始认证内容

设备标识使用 CodexQ 首次启用同步时生成的随机标识，不使用系统设备名称。

## 稳定事件标识

现有 `TokenUsageRecord` 只有时间、模型和 Token 数，不能作为可靠的跨设备去重键。方案要求解析阶段额外生成稳定事件标识：

- 从会话元数据读取稳定会话 ID，只在内存中使用。
- 对 Token 事件的必要计费字段做规范化。
- 使用“账本命名空间、会话 ID、规范化事件内容和同会话内重复序号”生成 SHA-256 标识。
- 账本只保存最终哈希，不保存生成哈希所用的原始会话 ID。
- 同一会话文件被复制、在另一台设备出现或被重复导出时，生成相同事件标识。
- 同一会话内两条内容完全相同的真实事件通过重复序号保留为两条，不能被错误折叠。

跨设备合并必须按事件标识取并集，不能继续使用整条 `TokenUsageRecord` 的值相等作为唯一去重依据。

## 文件布局

同步文件夹采用“清单 + 分设备月度账本”，不使用所有设备共同改写的单一总账文件。

- 根清单：记录格式版本、账本命名空间、创建时间和匿名账号指纹。
- 多台设备同时初始化空文件夹时，根清单只允许首个写入成功；其他设备重新读取并采用已落盘清单。
- 同账号清单因云端冲突发生替换时，后续成功同步自动采用文件夹中的权威命名空间。
- 设备目录：使用随机设备标识的哈希值命名。
- 月度账本：每台设备每月一个文件。
- 当前月份文件允许本设备原子替换。
- 已结束月份在内容稳定后视为只读，不再反复改写。
- 每台设备只写自己的设备目录，可以读取所有设备目录。

这套布局的目的：

- 两台 Mac 同时使用时不会改写同一个月度文件。
- iCloud Drive 延迟或冲突不会直接覆盖另一台设备的数据。
- 设备重装后即使生成新的设备标识，事件级去重仍能避免历史成本重复。
- 损坏单个账本文件时可以跳过该文件并继续显示部分结果。

所有写入先在同目录生成临时文件，完成编码和校验后再原子替换目标文件。临时文件不参与读取，并在下次成功同步时清理。

## 同一账号校验

为了防止同一个同步文件夹混入不同 Codex 账号：

- 首台设备创建账本时生成随机账本盐值。
- CodexQ 从本地认证信息中取得稳定账号标识，仅在内存中使用。
- 使用账本盐值生成匿名账号指纹，清单中只保存指纹。
- 后续设备必须生成相同指纹才能加入账本。
- 原始账号标识和认证令牌不得写入文件、日志或界面。

账号指纹无法取得时：

- Token 活动和本机 Token 成本仍正常工作。
- 不创建或加入同步账本。
- 设置中显示“无法确认 Codex 账号，成本同步未开启”。

账号指纹不一致时：

- 不读取、不合并、不覆盖现有账本。
- 设置中显示“所选文件夹属于另一个 Codex 账号”。
- 用户只能更换文件夹或停止同步，不提供强制混合入口。

## 同步流程

一次成本刷新按以下顺序执行：

1. 解析本机会话并生成带稳定事件标识的脱敏用量事实。
2. 同步关闭时，直接使用本机事实计算成本，行为与当前版本一致。
3. 同步开启时，先完成本设备当月账本的原子写入。
4. 读取清单和所有通过格式、账号、大小与字段校验的月度账本。
5. 将本机事实与账本事实按事件标识取并集。
6. 使用本机当前版本的定价目录重新计算成本。
7. 保存最近一次成功合并的脱敏结果和同步状态，供短暂失败时继续展示。

本地聚合缓存使用独立的 256 MB 上限，不受单个月度账本 16 MB 上限影响。缓存超过上限或写入失败时删除旧缓存并显示提示，不能静默回退到缺少设备的旧汇总。

美元金额不写入同步文件。这样不同版本的定价目录更新后，历史用量仍可重新计算，而不会永久保留过期金额。

## 刷新与离线行为

- 同步不能阻塞额度和 Token 活动刷新。
- 文件夹读取慢或不可用时，成本任务独立失败，不影响其他区域。
- 本机始终先完成成本计算；远端账本稍后合并成功时再更新成本区域。
- 开启同步后，手动刷新会同时触发本机账本导出和文件夹重读。
- 后台刷新沿用现有节奏，不增加高频文件轮询。
- 同一进程内按账本文件大小和修改时间复用已解码结果，只重新解码新增或变化的文件。
- 扫描每个账本前检查任务取消状态，关闭弹窗或刷新被替换时及时停止后续扫描。
- 无网络时继续解析本机会话并更新本设备账本；iCloud Drive 恢复后由文件系统同步。
- 读取到损坏或不支持的账本时跳过该文件，显示“部分设备账本未纳入成本”，不能让整个成本区域不可用。

## 状态模型

设置区域需要区分以下状态：

- `关闭`：不读写同步文件夹。
- `等待选择`：用户刚开启，但尚未成功选择文件夹。
- `正在同步`：正在导出本机账本或读取其他设备账本。
- `已同步`：最近一次写入和合并成功。
- `仅此设备`：同步正常，但尚未读取到其他设备账本。
- `同步延迟`：文件夹暂时不可访问，继续显示本机与上次合并数据。
- `部分数据`：部分账本损坏、版本不支持或读取失败。
- `账号不匹配`：所选账本不属于当前 Codex 账号，停止合并。

`已同步`状态可以显示最近成功时间和有效设备数，例如“2 台设备 · 刚刚同步”。不显示设备名称。

## 开关和文件夹生命周期

### 停止同步

- 立即停止读取和写入所选文件夹。
- Token 成本恢复为只统计本机。
- Token 活动保持不变。
- 保留本地选择记录以外的普通设置。
- 不自动删除同步文件夹中的历史账本，避免一台设备误删另一台设备的数据。

### 更换文件夹

- 先验证新文件夹，再切换当前选择。
- 新文件夹为空时创建新账本。
- 新文件夹已有同账号账本时加入现有账本。
- 新文件夹属于其他账号或版本不可兼容时拒绝切换，旧文件夹继续有效。
- 第一版不自动把旧文件夹数据迁移到新文件夹。

### 文件夹被移动或删除

- 开关保持开启，状态变为“同步延迟”。
- 不自动创建同名替代文件夹。
- 用户可以重新选择文件夹或停止同步。
- 本机成本继续工作。

## 隐私说明

设置说明和产品文档必须明确：

- CodexQ 不会把原始会话复制到 iCloud Drive。
- 账本可暴露模型名称、使用时间和 Token 数，这些仍属于使用元数据。
- 第一版只做字段脱敏，不额外加密账本内容。
- 同步文件夹的访问、传输和保留由用户选择的文件同步服务负责。
- 用户不应把账本文件夹设置为公开共享文件夹。

日志中只能记录状态、文件数量、账本版本和错误分类，不能记录完整路径、账号指纹、事件标识或账本内容。

## 兼容与迁移

- 同步默认关闭，因此升级后现有用户行为不变。
- 现有本机成本不需要迁移数据库；首次开启时从本机会话重新生成账本。
- 账本清单和月度文件都带独立格式版本。
- 新版本可以读取旧格式时应在内存中迁移，不擅自批量改写其他设备的历史文件。
- 遇到更高版本账本时跳过并提示更新 CodexQ，不能用旧格式覆盖。
- 关闭同步后不依赖账本缓存计算本机成本。

## 验证标准

### 数据正确性

- 同一会话文件出现在两台设备时只计一次。
- 同一会话在另一台设备继续产生新事件时，旧事件不重复，新事件正常加入。
- 同一会话内内容相同的两条真实事件不会被误删。
- 两台设备同时写入各自月度账本时互不覆盖。
- 设备重装并生成新设备标识后，历史事件不重复。
- 成本始终由用量事实和当前定价目录重新计算。
- 删除本机会话不会删除已经进入账本的历史事实。

### 隐私

- 自动化测试扫描清单和账本，确认不存在禁止字段。
- 账本中不出现原始会话 ID、账号 ID、用户名、设备名和完整路径。
- 账号不匹配时不读取成本记录，也不改写原账本。
- 日志与错误文案不泄露完整路径、指纹或事件标识。

### 产品行为

- 同步关闭时，Token 活动和 Token 成本行为与当前版本一致。
- 同步开关变化不触发 Token 活动数据源、模型或热力图变化。
- 开启同步后，Token 成本标签和说明按设备数切换：只有 1 台设备时仍显示本地口径，多设备时显示多设备口径。
- 用户取消文件夹选择后开关保持关闭。
- 文件夹暂时不可用时，额度和 Token 活动仍可刷新，本机成本仍可显示。
- 停止同步后立即恢复本机成本口径，不删除云端账本。
- 设置说明卡在关闭、正常和异常状态下使用本文指定的明确文案。

### 手工双机验收

- 在第一台 Mac 开启同步并选择 iCloud Drive 文件夹，确认显示“仅此设备”。
- 在第二台 Mac 选择同一文件夹，确认账号校验通过。
- 两台 Mac 分别产生新 Token 用量，等待文件同步后确认成本合计一致。
- 将一台 Mac 断网继续使用，确认两台设备恢复联网后无重复、无丢失。
- 临时移走同步文件夹，确认两台设备的 Token 活动不受影响，成本显示同步延迟而不是归零。

## 实施边界

实现时应保持现有结构：

- Token 活动继续由 app-server 路径负责。
- Token 成本读取器负责本机会话事实。
- 新增独立账本与合并服务，不让文件同步逻辑进入成本计算器。
- 成本计算器只接收已经去重的用量事实，不感知文件夹或设备。
- 设置状态负责开关、文件夹选择和同步状态展示。
- Store 负责并发刷新与失败保留，不让同步任务阻塞额度和 Token 活动。

不引入 Core Data、SwiftData、数据库、后台服务器或通用同步框架。第一版只解决两台或少量 Mac 的同账号成本汇总。
