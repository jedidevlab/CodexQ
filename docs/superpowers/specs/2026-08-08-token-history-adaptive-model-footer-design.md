# Token 历史模型分布自适应与底部注释设计

## 目标

让“模型分布”卡片的纵向高度随实际模型数量自然增减，消除模型较少时的大块空白。同时把历史页的所有数据说明和状态注释统一移动到“模型分布”卡片下方，并让“API 价格估算，非实际订阅账单”成为页面最后一行。

## 布局与交互

- “模型分布”卡片继续横向铺满可用宽度，不改变模型名称、条形图、数值和 Token/成本切换控件的排列。
- 有模型数据时，移除模型列表固定的最小高度，由标题、指标切换和实际模型行数共同决定卡片高度。
- 模型压缩规则保持不变：最多展示前八个模型加“其他”，因此卡片高度有明确上限。
- 没有模型数据时，沿用现有紧凑空状态，避免卡片完全塌缩。
- 页面顶部只保留标题、日期范围控件和摘要卡，不再显示数据质量或价格估算注释。
- “模型分布”卡片下方新增统一的底部说明区：先显示数据范围、官方活动覆盖、未计价 Token、跳过文件、同步状态、警告和刷新错误；最后一行固定显示“API 价格估算，非实际订阅账单”。
- 底部说明沿用 caption 字号和语义颜色：普通说明使用次级文字，未计价与警告使用橙色，刷新错误使用红色。

## 实现边界

- 只调整 `TokenHistoryView` 和 `TokenModelBreakdownChart` 的布局，不修改 Token 聚合、成本计算、模型排序或压缩规则。
- 不新增高度配置或模型数量档位；使用 SwiftUI 内容固有尺寸，避免重复维护行高与间距常量。
- 不改变窗口默认尺寸、最小尺寸、滚动行为和图表响应式双栏规则。
- 不修改其他页面的注释位置。
